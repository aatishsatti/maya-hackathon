## The scam family question (this change)
Live bugs: A) lottery / photo / call scams never asked the family question; B) a late "yes" answered "Done" but only sent a generic contact request; C) the open question was lost after a gap.
Causes in code:
- `chat.js afterTalkReply`: registered the open family question whenever the verdict was warn, even when her reply was the link/photo request (reconfirm), so later replies were told "the question is already open" (`official.js answeredNote`, `familyState.pending`) and it was never asked.
- `care.js`: the open question dropped after two non-answers (`scamUnclear`, `left`) or 20 minutes (`SCAM_ASK_MS`). With nothing pending, `call.js careNotes` took "please let my family know" as the generic `familyAsk` and Spark said "Done".
What it does now:
- `care.scamAsk(..., {asked})`: the question is registered ASKED only if her reply really put it (`care.asksFamilyQ`); otherwise it is OWED and the next reply is told to ask it (`scam-family-owed`). Every reply is scanned (`care.scamAskedOut`).
- It stays open 24 h (`SCAM_OPEN_MS`); unclear answers no longer drop it. A yes counts only while FRESH (asked < 15 min ago and < 2 non-answers). Otherwise `scam-resume`: she restates the worry (topic only) and asks again; the generic family note is NOT sent.
- After 24 h an unanswered incident is remembered (`care.scamLost`, 7 days): a yes / "let my family know" gets `scam-lost` (plain "I lost that set-up", asks what happened), nothing is sent until the answer.
- Chat retry: if Spark skips a required question twice, a plain question closes her reply (`chat.js`, labels setrem-* and scam-*).
- `FAMILY_CLAIM` also blocks "I'm letting your family know now" when nothing was sent. Chat sessions now carry `scamAt`, so "okay" after a scam talk is not read as a health emergency.
- Unchanged: the detector (`scam.js`), the held-out numbers (37/38 warned, S114 cautioned, 0/38 false), false-yes protection (`saysYesToFamily`), "a no covers the incident" (`care.scamDeclined`), topic-only family text, voice / push / WhatsApp / reminders.

## Fifth round (her own reminder power) - local, not pushed
Live bug: "can u start with reminding me to take my headache meds in 1 minute" got "I don't set one-minute reminders / I can't create timers, your son can add a reminder" (both false). Cause: `setrem.IS_REQUEST` only matched the literal "remind me" / "set a reminder", so "start with reminding me" (also "tell me in 1 minute", "ping me", "set a timer") never entered the set-up and Spark improvised a limit. Changes: wider `IS_REQUEST` (+ "reminding me", "start with reminding", "tell me / let me know / ping me in N units", "set a timer"), timer lengths ("a 5 minute timer", "timer for 1 minute"), cleaner task words, a negative guard (stop / keep reminding me, a bare "do you set reminders?"); `REMINDER POWER` fact in `call.js limitsFacts` whenever reminders / timers come up (sets them herself, from one minute, no minimum, never send them to family); the abilities list item (2) now says she sets reminders herself; `chat.js` rewrites a draft that refuses / invents a limit / sends them to family, and one that says set / done before the app saved; two ways named ("text or voice note") are never guessed, they pick ONE (`readDelivery` multi). No minimum time exists in code (one minute works). Order kept: say back -> yes -> how -> save.

## Sixth round (no how question, source channel, unseen call) - local, not pushed

## Live fixes after Mathew's 2:35 am test (3 Nov, local commit on top of ea3fde8, NOT pushed)
Confirmed live FAILS fixed in code (none re-tested live): (1) voice hang-up, (3) ring vanishing, (5) natural yes. Removed that dismiss; `_dropIncoming` (answer, decline, server end, ringMs+3 s timer) now dismisses it, so it clears WITH the end. Earlier fixes kept.
- 5 Natural yes: `social.isYes` accepts only yes-words and filler (yes, yes please, yes perfect, yes that sounds good, sure, perfect...) and still refuses quotes, questions and anything with other words; it counts only as the answer to the confirm question. The SAVED text now asks for ONE sentence with time + start day + skip / change / cancel.
- Precaution only (untested, not a live fix): a call that starts while a chat is queued/ringing now closes the record cleanly (it used to stay "calling" and block later days) and a call's start message already counts as busy (`care.callStarting`); the pickup instruction now says whose chat it is from the saved record and refuses family / welfare / "thinking about you" wording.
